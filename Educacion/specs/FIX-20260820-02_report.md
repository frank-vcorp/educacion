## A. Síntoma y alcance

- Defecto hermano del diagnosticado en FIX-20260820-01: `services/planeaciones/update-actions.ts`
  es un módulo con directiva `'use server'` (línea 15) que exportaba un valor no-función en línea 243:
  `export const F3_CAMPOS_PULIBLES = F3_CAMPOS;` (array de los 4 campos pulibles F3).
- El bundle compilado pre-fix de `/planeaciones/[id]` ya contenía el check runtime
  `ensureServerEntryExports([updateBloque, updatePlaneacion, F3_CAMPOS_PULIBLES])` y el manifiesto
  de acciones le asignó el action ID `d9c42bd95b440200a9093d121162853b8a7d783f`.
- Alcance funcional: **cualquier invocación de `updateBloque` o `updatePlaneacion` en producción
  lanzaría el mismo 500** que FIX-01 observó en `/alumnos` — es decir, la aceptación de sugerencias
  IA en los tres flujos (F1 variante de bloque, F2 ayuda a redacción, F3 pulir PDF) y la edición
  inline de bloques (`bloque-editor.tsx`). Flujo central de planeaciones. El fallo dispara en la
  primera evaluación del módulo (primera invocación de cualquiera de sus acciones).
- El export tenía **0 consumidores** en el repo (grep global: sólo la definición y la mención en
  FIX-20260820-01 §I R1).

2. **Post-fix (runtime):** `rm -rf .next && pnpm build` + `pnpm start -p 3112` + invocación de ambas
   acciones vía HTTP con su action ID compilado:

## E. Causa raíz

`services/planeaciones/update-actions.ts` exportaba un valor no-función (`F3_CAMPOS_PULIBLES`,
array, **sin ningún consumidor en el repo**) dentro de un módulo `'use server'`. Next.js inyecta
`ensureServerEntryExports([...exports])`, que se ejecuta en **runtime** en la primera evaluación
del módulo (primera invocación de cualquiera de sus acciones). El array (`typeof 'object'`) lanza
el error y tumba el request con 500. El build no valida esta condición (el `pnpm build` pre-fix
pasaba), así que el defecto pasa CI y despliegue y explota con el primer uso. Causa confirmada:
mecanismo demostrado con reproducción runtime completa en FIX-20260820-01 (defecto idéntico, mismo
Next 14.2.35, mismo validador, mismo string de error) + evidencia estática pre-fix en el bundle de
este módulo + contra-reproducción post-fix (bundle limpio y acciones respondiendo 200).

## F. Solución aplicada (mínima, sin alterar runtime ni contrato F1/F2/F3)

En `services/planeaciones/update-actions.ts`:

- Eliminado `export const F3_CAMPOS_PULIBLES = F3_CAMPOS;` (export muerto, 0 consumidores).
- Añadida nota técnica (6 líneas) documentando por qué `F3_CAMPOS` permanece como constante
  interna sin exportar (invariante `'use server'`).
- **Conservado intacto:** `F3_CAMPOS` interna (la usa `updatePlaneacion` para el filtrado de
  campos F3); los exports async `updateBloque`/`updatePlaneacion` (firmas, lógica y comportamiento
  sin cambio); los type-exports `UpdateBloqueInput`/`UpdateBloqueResult`/`UpdatePlaneacionInput`/
  `UpdatePlaneacionResult` (contrato TS de los callers, borrados al compilar, no violan el contrato
  runtime). Ningún importador afectado.
