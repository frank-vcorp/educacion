## D. Hallazgos priorizados

### P1-1 — `e2e/entrevista-inicial.mobile.spec.ts` falla en `--project=mobile` por ausencia de `<meta name="viewport">` en el fixture
- **Evidencia:** `pnpm exec playwright test e2e/entrevista-inicial.mobile.spec.ts --project=mobile --reporter=list` → `expect(metrics.docScrollWidth).toBeLessThanOrEqual(375)` falla con `Received: 981` (línea 243 del spec). La aserción `expect(vp).toEqual({ width: 375, height: 812 })` (línea 209) pasa — el viewport de Playwright es 375×812, pero el navegador renderiza el HTML a 980px de ancho por defecto porque el fixture no tiene `<meta name="viewport" content="width=device-width">`. En `--project=mobile` (Pixel 5, `isMobile: true`), la ausencia del meta tag hace que el browser use el rendering mobile por defecto (~980px).
- **Impacto:** Medio. La afirmación de IMPL-04 §5.3.D ("El nuevo spec es descubierto por ambos proyectos (`chromium` y `mobile`) ... Doble gate de cobertura") es **incorrecta**: el test solo pasa en `--project=chromium`; en `--project=mobile` falla con `docScrollWidth=981`. El gate de viewport móvil no funciona como se documenta. Sin embargo, el gate principal (`chromium`) sí valida el fixture a 375×812, y la validación con Tailwind real + `0022` aplicada sigue siendo gate de staging.
- **Recomendación:** Añadir `<meta name="viewport" content="width=device-width, initial-scale=1">` al `<head>` del fixture HTML en `e2e/entrevista-inicial.mobile.spec.ts` (línea ~50). Fix de 1 línea. SOFIA vía INTEGRA (L2, mejora cobertura; 1 línea).
- **Condición de cierre:** `pnpm exec playwright test e2e/entrevista-inicial.mobile.spec.ts --project=mobile` → PASS, con `docScrollWidth=375` y métricas equivalentes a la corrida chromium.

### P3-1 — `entrevista-inicial.mobile.spec.ts` usa CSS inline en lugar del bundle real de Tailwind
- **Evidencia:** El fixture HTML (líneas 51-123) declara estilos inline (`max-width: 768px`, `width: 100%`, `height: 40px`) que reproducen las reglas CSS equivalentes a Tailwind. Si Tailwind cambiara el valor de `max-w-3xl` o `w-full` en `tailwind.config.ts`, este test no lo detectaría automáticamente.
- **Impacto:** Bajo. Los valores validados (max-width 768px, width 100%, height 40px) son los que actualmente produce Tailwind con la config del proyecto. Una regresión en el bundle real de Tailwind sería atrapada por la inspección visual de staging con `playwright_browser_resize` y la app levantada con `0022` aplicada. Ya documentado en IMPL-04 §10.2 (R-IMPL-04-1).
- **Recomendación:** Aceptar el riesgo para sandbox. La verificación con Tailwind real + `0022` aplicada sigue siendo gate de staging.
- **Condición de cierre:** Inspección visual mobile 375×812 con Tailwind real en staging (sin scroll horizontal).

### P3-2 — Botones `h-10` (40px) en lugar de ≥44px de la SPEC
- **Evidencia:** Las métricas del test reportan `btnArchivarHeight: 40, btnGuardarHeight: 40`. El SPEC P-UX4 pide ≥44px. shadcn/ui default `Button` usa `h-10` (40px). El test lo verifica como observación (`>= 40`), no como bloqueo.
- **Impacto:** Bajo. Patrón pre-existente de shadcn (no introducido por IMPL-04). Para llegar a 44px se necesita `size="lg"` (`h-11`) o `size="icon"` con padding adicional. Ya documentado en IMPL-04 §10.2.
- **Recomendación:** Trabajo L2 (no contractual). No bloquea el incremento.
- **Condición de cierre:** Si Frank decide ajustar a 44px, cambiar `Button` a `size="lg"` en `entrevista-inicial-form.tsx`.

### P3-3 — `entrevista-inicial.spec.ts` con skip condicional no se ejecuta en sandbox
- **Evidencia:** El spec original ahora usa `test.skip(!FULL_FLOW_ENABLED, SANDBOX_SKIP_REASON)`. En sandbox (sin `E2E_FULL_FLOW=1`), el test se salta con motivo visible en el reporter. La ejecución real con Supabase + `0022` aplicada es gate de staging.
- **Impacto:** Bajo. Es el comportamiento esperado y documentado. El motivo del skip queda visible (no es un skip ciego como antes).
- **Recomendación:** Mantener. Frank debe autorizar `supabase db push` y ejecutar con `E2E_FULL_FLOW=1` en staging.
- **Condición de cierre:** E2E completo PASS en staging con `E2E_FULL_FLOW=1`.
