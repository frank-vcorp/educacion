## 5. Hallazgos priorizados

### F-01 [P3] — Duplicado del tipo `Directorio` en el export del service
- **Evidencia:** `services/alumnos/entrevista-actions.ts:314` — `export type { Directorio, EntrevistaInicialV2, EstadoEntrevista, RespuestasV2 };`. `Directorio` ya se importa de `@/types/entrevista` (línea 35) y el `export type` lo re-emite. No genera error de TypeScript (deduplicación de type-only exports) pero es ruido.
- **Impacto:** cosmético; sin efecto funcional ni de seguridad.
- **Owner:** SOFIA (fix trivial).
- **Condición de cierre:** opcional; no bloquea el cierre.

### F-02 [P3] — `alumno.grado` se pasa al form pero no se usa
- **Evidencia:** `app/(app)/alumnos/entrevista-dialog-content.tsx:50` — `alumno={{ id: alumnoId, nombre: alumnoNombre, grado: alumnoGrado }}`. `components/alumnos/entrevista-inicial-form.tsx` no referencia `alumno.grado` en ninguna parte (verificado por grep).
- **Impacto:** cosmético; prop muerta.
- **Owner:** SOFIA (fix trivial).
- **Condición de cierre:** opcional; no bloquea el cierre.

### F-03 [P3] — Fixture del mobile spec (v1) desactualizado respecto al contrato v2
- **Evidencia:** `e2e/entrevista-inicial.mobile.spec.ts:131-179` — el fixture HTML reproduce 21 ítems con las preguntas de v1 (DEC-20260820-01, superseded). El componente real es v2 (23 ítems). Este spec es de IMPL-20260820-04 (P3-4) y **no fue modificado por IMPL-20260820-08** (verificado: `git diff -- e2e/entrevista-inicial.mobile.spec.ts` → vacío; `git log --oneline -- e2e/entrevista-inicial.mobile.spec.ts` → solo commit `7d5eabd`).
- **Impacto:** el spec valida viewport/CSS con un fixture estático; no valida el contenido real del componente. Es un test de layout, no de contenido. Mantenibilidad: el fixture está desactualizado.
- **Owner:** SOFIA (actualización del fixture a v2 en un IMPL futuro).
- **Condición de cierre:** actualizar el fixture a 23 ítems con las preguntas v2; no bloquea el cierre de IMPL-20260820-08.

### F-04 [P3] — Sin implementación real del bucket `entrevista-evidencia`
- **Evidencia:** `components/alumnos/entrevista-inicial-form.tsx:534-536` — usa `URL.createObjectURL(file)` para previsualización local. El contrato `evidencia: { url, mime }` persiste con un object URL local. La columna acepta `null` por celda, por lo que diferir la carga real al bucket no rompe el contrato.
- **Impacto:** ya documentado en SPEC §14 R9-9 (MEDIO) y en IMPL report §4. Las evidencias de dibujo de menores (R9-9) no se suben a Storage; el contrato permite `evidencia: null` y diferir la carga.
- **Owner:** SOFIA (crear bucket + integración Storage) o Frank (diferir a IMPL posterior).
