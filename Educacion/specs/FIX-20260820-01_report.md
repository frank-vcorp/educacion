## A. Síntoma y alcance

- Deployment Vercel `dpl_7srSHvhEMtEGG2kBeS4hf3g2yodi`: logs muestran en `/alumnos` el error
  `Error: A "use server" file can only export async functions, found object.`
  (https://nextjs.org/docs/messages/invalid-use-server-value).
- Alcance funcional: **todo el flujo de entrevista inicial por alumno está roto en producción** —
  cualquier invocación de server action desde `/alumnos` (abrir la entrevista → `getEntrevista`,
  guardar → `upsertEntrevista`, archivar → `archivarEntrevista`) devuelve 500. La página en sí
  renderiza; el fallo dispara al invocar una acción (RSC/action request sobre `/alumnos`).

## B. Reproducción

Determinista, sin autenticación, en local (Next 14.2.35, Node 22.23.1):

1. `pnpm build` → **EXIT 0**. El build NO falla: la validación de exports `'use server'`
   es **runtime**, no de compilación. Por eso Vercel desplegó sin error y el fallo apareció
   sólo al recibir tráfico. (Descartado también `.next` cacheado: build limpio reproduce igual.)
2. `pnpm start` + invocación de la acción vía HTTP:
   ```
   curl -X POST http://localhost:3111/alumnos \
     -H "Next-Action: cdb861d034a4b5c06f97de2dd5c92fbb92979db5" \
     -H "Content-Type: text/plain;charset=UTF-8" --data '[]'
   ```
   (`cdb861d0…` = action ID compilado de `getEntrevista` en el manifiesto de `/alumnos`).
3. Resultado pre-fix: **HTTP 500** con el error exacto de Vercel en el log del servidor:
   ```
   Error: A "use server" file can only export async functions, found object.
       at r (.next/server/chunks/6952.js)               ← ensureServerEntryExports
       at 39356 (.next/server/app/(app)/alumnos/page.js) ← evaluación del módulo entrevista-actions
   ```
   Trigger productivo equivalente: la docente abre la entrevista de un alumno
   (`EntrevistaDialogContent` → `getEntrevista(alumnoId)`), o cualquier otra acción del módulo.

## C. Evidencia

1. **Fuente** (pre-fix): `services/alumnos/entrevista-actions.ts` es un módulo con directiva
   `'use server'` (línea 28) que exportaba un objeto en línea 306:
   `export const __test_only__ = { ENTREVISTA_ESTADOS, validateCuestionarioV2, getGrupoActivo, getAlumnoForDocente, docenteAceptoAviso };`
2. **Mecanismo de Next 14.2.35**: `node_modules/next/dist/build/webpack/loaders/next-flight-loader/action-validate.js`
   define `ensureServerEntryExports(actions)`, que lanza el error exacto si algún export no es
   `typeof 'function'`. El transform SWC inyecta esa llamada al final de cada módulo `'use server'`
   y registra **todos** los exports en el manifiesto de acciones (a `__test_only__` le asignó el
   action ID `1577d04685d3cc467b58b9874168813b2b481da1`).
3. **Bundle compilado pre-fix**: `.next/server/app/(app)/alumnos/page.js`, módulo 39356, termina con
   `(0,C.h)([O,I,P,$])` = `ensureServerEntryExports([getEntrevista, upsertEntrevista, archivarEntrevista, __test_only__])`,
   evaluada al cargar el módulo. `$` es el objeto → throw. El módulo se evalúa lazy en la primera
   invocación de acción (el manifiesto usa `Promise.resolve().then(require)`), por eso el GET inicial
   a `/alumnos` podía responder y el 500 aparecía al usar la entrevista.
4. La cadena del error en Vercel es idéntica (string literal único de `action-validate.js`);
   `found object` = `typeof __test_only__`.

## E. Causa raíz

`services/alumnos/entrevista-actions.ts` exportaba un valor no-función (`__test_only__`, helper de
tests **sin ningún consumidor en el repo**) dentro de un módulo `'use server'`. Next.js inyecta
`ensureServerEntryExports([...exports])`, que se ejecuta en **runtime** en la primera evaluación del
módulo (primera invocación de cualquiera de sus acciones). El objeto lanza el error y tumba el
request con 500. El build no valida esta condición, así que el defecto pasó el CI y el despliegue y
explotó en producción con el primer uso de la entrevista. Causa confirmada (reproducción + mecanismo
+ eliminación del fallo al quitar el export).

## F. Solución aplicada (mínima, sin alterar runtime ni contrato)

En `services/alumnos/entrevista-actions.ts` (−16 líneas, puras remociones):

- Eliminado `export const __test_only__` y su comentario de sección. Cero consumidores: los tests
  importan `validateCuestionarioV2`/constantes desde `@/types/entrevista` y ejercen los helpers
  internos (`getGrupoActivo`, `getAlumnoForDocente`, `docenteAceptoAviso`) indirectamente vía las
  acciones públicas; ningún archivo del repo referencia `__test_only__`.
- Eliminado `export type { Directorio, EntrevistaInicialV2, EstadoEntrevista, RespuestasV2 };`
  (re-export sin consumidores — todos importan los tipos de `@/types/entrevista`; QA-20260820-06 ya
  lo señalaba como ruido). Los type-exports se borran al compilar y no violan el contrato runtime,
  pero se retiró para que el módulo conserve **sólo exports async**, conforme a la instrucción.
- Removidos los imports que quedaron sin uso (`ENTREVISTA_ESTADOS`, `Directorio`,
  `EstadoEntrevista`, `RespuestasV2`).

Contrato público intacto: `getEntrevista` / `upsertEntrevista` / `archivarEntrevista` conservan
firmas, comportamiento y **action IDs estables** en el manifiesto compilado post-fix
(`cdb861d0…`, `f67b9c25…`, `6bc44d0e…`), verificado en el bundle nuevo.
