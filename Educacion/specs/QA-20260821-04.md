### AC-1 — Portal del drawer a `<body>` escapa del containing block de `backdrop-filter`
- **Implementación:** `nav-menu.tsx:134-225` — bloque del drawer envuelto en `createPortal(..., document.body)`. La jerarquía React sale del `<header>`; el DOM resultante tiene el drawer como hijo directo de `<body>` (cuya `backdrop-filter: none` permite que el viewport sea el containing block para `position: fixed; inset: 0`).
- **Evidencia:** `test-results/header-nav.mobile-FIX-2026-b5359-e-viewport-portal-aplicado--mobile/evidence/header-nav-fixed-drawer-open-375x812.metrics.json` → `drawer {x:0,y:0,width:375,height:812}`. Equivalente 360×640 → `drawer {x:0,y:0,width:360,height:640}`. CONTROL A/B: `headerHeight=57`, `drawerHeight=56`, `drawerEqualsHeader=true` (estado roto confirmado).
- **Resultado:** **PASS**.

### AC-2 — Portal queda **fuera** del `backdrop-filter` (header preserva el blur)
- **Implementación:** `app-header.tsx:13` queda intacto con `backdrop-blur`; el portal React mueve el árbol del drawer (no el nodo del header) fuera del `<header>`.
- **Evidencia:** `git diff app/(app)/_components/app-header.tsx` → vacío. CSS compilado por `pnpm build` mantiene `-webkit-backdrop-filter: blur(8px); backdrop-filter: blur(8px)` en el header. Métricas CONTROL A/B confirman que el header con blur + drawer dentro = bug; drawer fuera = fix.
- **Resultado:** **PASS**.
