## 4. Hallazgos

### F-4 [P2] — `stepper.inViewport` (y por simetría `footer.inViewport`) evalúan a número, no a booleano, por precedencia de `??` vs `<=` (preexistente, no introducido por este IMPL)

- **Evidencia:**
  - Comando: `pnpm exec playwright test e2e/entrevista-inicial-stepper.mobile.spec.ts`.
  - Error literal: `expect(initial.stepper.inViewport).toBe(true)` → `Received: 163`.
  - Líneas implicadas (no modificadas por este IMPL): `e2e/entrevista-inicial-stepper.mobile.spec.ts:267-275`:
    ```ts
    stepper: {
      inViewport: rect(stepper)?.bottom ?? 0 <= 812,
      bottom: rect(stepper)?.bottom ?? 0,
    },
    footer: {
      inViewport: rect(footer)?.bottom ?? 0 <= 812,
      bottom: rect(footer)?.bottom ?? 0,
      height: rect(footer)?.height ?? 0,
    },
    ```
  - Causa raíz: en JavaScript, el operador `??` tiene **menor** precedencia que los operadores relacionales (`<=`, `>=`, etc.). Por tanto `rect(stepper)?.bottom ?? 0 <= 812` se parsea como `rect(stepper)?.bottom ?? (0 <= 812)`, es decir `rect(stepper)?.bottom ?? true`. Cuando `bottom = 163`, el resultado es el número `163` (truthy), no `true`.
  - Reproducción aislada: ejecutado `node -e "const fn = (rect) => rect?.bottom ?? 0 <= 812; console.log(fn({bottom: 163}))"` → imprime `163` (confirmado en sandbox).
- **Impacto:** el gate `MOBILE-1` sigue rojo en CI/staging aunque **F-1 esté cerrado**. La assertion rota no fue detectada por QA-20260821-01 porque el test moría antes en la assertion de `maxHeight`; al arreglar F-1, este segundo bug queda al descubierto.
- **Severidad QA:** P2 (mismo nivel que F-1; un solo caracter/paréntesis resuelve el bug; sin cambio funcional, sólo test).
- **Owner recomendado:** SOFIA en nueva sesión independiente (un cambio mínimo de ~2 caracteres `??` → con paréntesis `(... ?? 0) <= 812` o equivalente explícito; sin tocar código de producto).
- **Condición de cierre:** comparar `(rect(stepper)?.bottom ?? 0) <= 812` (paréntesis) o `Boolean(rect(stepper)?.bottom && rect(stepper)!.bottom <= 812)` (explícito). Mismo patrón en `footer.inViewport`. Una vez parcheado, el e2e stepper debe pasar completo en `chromium` y `mobile`.
- **Acción ATLAS:** pivote a sesión SOFIA dedicada a este fix (alcance ≤ 5 líneas, sin contratos públicos, sin producto) y re-correr gate e2e antes de promover a staging.
