## 3. Decisiones técnicas (SOFIA, reversibles)

### 3.1 Ubicación de la UI — Dialog por fila (en lugar de ruta `/alumnos/[id]`)

El handoff proponía dos opciones: (a) Dialog en `alumnos-manager.tsx`, (b) ruta `app/(app)/alumnos/[id]/page.tsx`. Se eligió **(a) Dialog** porque:

- SCN-20260820-04 dice "abrir su perfil y registrar la entrevista"; el Dialog sobre la fila del alumno mantiene el contexto de la lista sin obligar a una navegación adicional.
- P-UX1 ("una pregunta/grupo por pantalla"): con scroll vertical dentro del modal, los 21 ítems siguen la lectura secuencial infantil.
- Mobile-first (P-UX4): un Dialog full-width es más usable a 375×812 que una página que hereda el padding del layout `(app)`.
- Reversible: si Frank prefiere ruta dedicada, se puede mover `EntrevistaDialogContent` a `app/(app)/alumnos/[id]/page.tsx` con un cambio de 1 import.

### 3.2 Wrapper del Dialog = server component (`entrevista-dialog-content.tsx`)

`AlumnosManager` es `'use client'`. Para invocar `getEntrevista` (server action) antes de abrir el modal, se hace en un **server component** que se renderiza dentro del `DialogContent`. Esto:

- Mantiene la fila del alumno controlada desde el cliente (state, dialog open/close).
- Carga la entrevista una sola vez al abrir el modal (no en cada render de la lista).
- Permite posterior `revalidatePath('/alumnos')` desde las server actions para refresco automático.

### 3.3 Validación zod espejo de la BD (sin JSON Schema en runtime)

SPEC_TEC_09 §5.1 declara que la BD no impone JSON Schema en runtime para no acoplar la migración a un validador externo. El servidor valida con `validateCuestionarioLiteral` (zod espejo):

- `array(items).length(21)` (AC-7.a).
- `orden` 1..21 por ítem (AC-7.a).
- `pregunta` idéntica a la tabla §4 (AC-7.b). Esto hace imposible que un cliente con sesión válida envíe un cuestionario alterado.

### 3.4 Una sola fila por (alumno, ciclo, tipo)

D9-03: `unique (alumno_id, ciclo_escolar, tipo_entrevista)`. El `upsert` server action usa `onConflict: 'alumno_id,ciclo_escolar,tipo_entrevista'` para garantizar idempotencia (AC-6.c, AC-11 idempotencia).

### 3.5 `tipo_entrevista` server-side only

`tipo_entrevista` es `default 'nino'` en la BD y NUNCA se acepta desde el cliente (se asigna en el payload del `upsertEntrevista`). Esto cierra contractualmente la decisión funcional "no se infieren preguntas familiares" (OQ-20260820-04).

### 3.6 Estado 'archivada' mostrado como Input read-only

El Select muestra sólo "Borrador" / "Completa" (los dos únicos estados que el docente puede asignar manualmente). Si la entrevista está `archivada`, el campo se convierte en un `<Input readOnly>` con el texto "Archivada" (no editable). El cambio a `archivada` se hace exclusivamente con el botón "Archivar" (acción reversa: no hay `desArchivar`).

## 8. Desviaciones, riesgos y notas

### 8.1 Desviaciones

**Ninguna** respecto a SPEC_TEC_09, ADR-20260820-02 y el handoff. La implementación reproduce el contrato textual; las decisiones reversibles de SOFIA (ubicación UI Dialog, server-component wrapper del modal, `archivada` como input read-only) están documentadas en §3 y son compatibles con cualquier reversión.

### 8.2 Riesgos

- **Bajo (R-IMPL-03-1):** El `viewBox` exacto del cuestionario en mobile 375×812 no se verificó visualmente en el sandbox (no hay `playwright_browser_resize` con la app levantada con `0022` aplicada). El diseño usa `flex`/`grid` con `max-w-3xl` en el Dialog, inputs a `w-full`, padding responsivo (`sm:p-6`) y `field-group` con scroll natural — no hay tablas, `position: fixed` ni anchos fijos. **Validación visual queda como gate de staging** (AC-10).
- **Bajo (R-IMPL-03-2):** El patrón del Dialog depende de `getEntrevista` ejecutándose **al renderizar el server component `entrevista-dialog-content.tsx`**. Si la consulta tarda (RLS + JSONB), el modal se demora en abrir. Mitigación: en producción, `entrevista_inicial_alumno` tiene un índice `idx_entrevista_alumno` (`0022:45`) que hace la búsqueda O(1) por `alumno_id`. Costo esperado: <50ms.
- **Bajo (R-IMPL-03-3):** Si dos docentes distintas editan la entrevista del mismo alumno simultáneamente (escenario teórico), la última escritura gana. El `updated_at` y el `updated_at` del trigger reflejan la última edición. No hay `version` porque la decisión D1 lo prohíbe. Si Frank pide concurrencia optimista, se añade una columna `version int` aditiva.
- **Bajo (R-IMPL-03-4):** El `anonymizer` (R-IA-10 fail-closed) no se aplica a `entrevista_inicial_alumno` porque la tabla NO se envía a IA (AC-8). La garantía es estática (grep). Si en el futuro Frank quiere enviar la entrevista a IA (cambia D9-05), hay que actualizar el `anonymizer` para no romper la regla dura LFPDPPP de "cero datos de menores a IA" (SPEC_MVP §3.7.2).

### 8.3 Compatibilidad

- **Mobile-first (P-UX4):** Dialog full-width, inputs a 100% width, sin tablas. Las validaciones AC-10 quedan para staging.
- **Accesibilidad WCAG 2.1 AA:** Labels asociados (`<Label htmlFor="id">`), `aria-label` en botones, `aria-readonly` para el campo archivado, focus visible heredado de shadcn, navegación por teclado funcional.
- **Sin emojis en UI de producto (P-UX):** verificado. Iconos de `lucide-react` (`Loader2`, `FileText`, `Archive`, `ClipboardList`, `Pencil`, `Trash2`, `UserPlus`, `Search`) sin emojis.
- **Anti-doble-submit:** botón "Guardar" deshabilitado durante `isPending`; "Archivar" deshabilitado durante `isArchiving`. Tras guardar, estado actualizado vía `revalidatePath('/alumnos')`.

### 8.4 Cumplimiento de Discovery / privacidad

- **OQ-20260820-04 (familia fuera):** `tipo_entrevista` es `'nino'` único en el `check` de la BD. No se infieren preguntas familiares.
- **FND-20260820-06 (datos sensibles):** la tabla guarda emociones (13-16), datos de terceros (3-6) y convivencia (5) con gate A1 (aviso) y visibilidad restringida (B1, sin acceso de director). Cumple LFPDPPP y D-FIN-15.
- **SCN-20260820-04 (edición sin mezclar ciclos):** `unique (alumno_id, ciclo_escolar, tipo_entrevista)` + `upsert` idempotente lo garantizan.
- **SCN-20260820-05 (protegida frente a IA):** AC-8 verificado (0 referencias en capa IA).
