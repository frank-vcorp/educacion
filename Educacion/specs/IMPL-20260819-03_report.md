## Detalle técnico de los cambios

### `services/planeaciones/planeacion-actions.ts`

**FIX P3-N1 — path `errSes` (líneas 487-502)**

```ts
if (errSes) {
  // FIX P3-N1 (IMPL-20260819-03): SELECT de sesiones origen ocurre tras
  // crear la planeación (paso 4). Si falla, la planeación quedaría
  // huérfana. Compensamos invocando compensarClonado (sesionesCreadas
  // está vacío aquí → sólo borra la planeación recién creada).
  const compensada = await compensarClonado(
    supabase,
    nuevaPlaneacionId,
    sesionesCreadas,
  );
  if (!compensada) {
    return {
      ok: false,
      error: `Falló la compensación del clonado; revisar filas huérfanas para planeacion_id=${nuevaPlaneacionId}`,
    };
  }
  return { ok: false, error: errSes.message };
}
```

**FIX P3-N3 parte i — 4 call sites capturan el booleano (líneas 498-606)**

Cada call site ahora declara `const compensada = await compensarClonado(...)`; si `!compensada`, retorna el mensaje verbatim; si `compensada === true`, retorna el error original. Aplicado a:
- `errSes` (línea 488) — 4º call site (N1).
- `errInsSes` (línea 514) — 1º call site.
- `errBloque` (línea 547) — 2º call site.
- `errInsBloque` (línea 579) — 3º call site.

Mensaje verbatim (handoff P2-FIXES Fix 2 punto 4):

```
Falló la compensación del clonado; revisar filas huérfanas para planeacion_id=<id>
```

**FIX P3-N3 parte ii — inspección de los 3 deletes en `compensarClonado` (líneas 617-705)**

Antes: sólo se inspeccionaba `{error}` del delete de `planeacion`. Ahora se desestructura `{error}` de los 3 deletes (`bloque`, `sesion`, `planeacion`); cada uno se loggea con `console.warn` (incluyendo `nuevaPlaneacionId` y la tabla) y retorna `false`. Sólo retorna `true` si todos los deletes aplicables (bloque si `sesionesCreadas` no vacío, sesion, planeacion) no devolvieron error y no hubo excepción. El `catch` externo se mantiene.

### `lib/pdf/generate.ts`

**FIX P3-N2 — `newPage()` dentro del lifecycle (líneas 332-359)**

```ts
let page: Awaited<ReturnType<typeof browser.newPage>> | undefined;
try {
  page = await browser.newPage();
  await page.setContent(html, { waitUntil: 'networkidle0', timeout: 30000 });
  const pdfUint8 = await page.pdf({...});
  const buf = Buffer.from(pdfUint8);
  return makePdfResult(buf);
} finally {
  await page?.close().catch(() => undefined);
  await browser.close().catch(() => undefined);
}
```

Comportamiento:
- `newPage()` OK → path de éxito sin cambio (page.close + browser.close en finally).
- `newPage()` lanza → `page` permanece `undefined`; el guard `page?.close()` del finally no aplica; `browser.close()` cierra el browser; el error de `newPage()` **se propaga** al caller (no se traga).
- `browser.close()` también lanza → `.catch(() => undefined)` traga el error de cierre; el error de `newPage()` (o de `setContent`/`pdf`) sigue propagando.

## Decisiones internas reversibles (§15 SOFIA)

1. **N2 — estructura del fix:** elegí `let page` declarado fuera del try con asignación dentro, y guard `page?.close()` en el finally. Alternativa rechazada: envolver `newPage()` con su propio try/catch que cierre el browser y relance (más código, mismo comportamiento).
2. **N3-ii — orden de inspección:** mantengo el orden físico de los deletes (bloque → sesion → planeacion) y agrego la inspección de `{error}` en cada uno. Si el primer delete falla, no se ejecutan los siguientes (corto-circuito). Esto preserva el orden inverso FK-safe del handoff P2-FIXES.
3. **Mock para verbatim del mensaje:** agregué un flag `useFixedUuid` en `failConfig` que hace `uuid()` derivar de un contador predecible. Esto permite a los tests AC-P3-3 y AC-P3-4 conocer el `nuevaPlaneacionId` de antemano y assertar el verbatim. Sólo afecta los tests que activan el flag (no los tests preexistentes).
