## Decisiones reversibles SOFIA (documentadas para que INTEGRA las confirme o revoque)

1. **`createBloque` auto-crea una sesión por defecto** si la planeación no tiene ninguna (`numero=1, fase_interna='inicio', estado='pendiente'`). Esto porque `bloque.sesion_id` es NOT NULL (0010:62) y el wizard actual (`wizard-planeacion.tsx:694`) crea planeaciones MVP sin sesiones. Si INTEGRA prefiere que la UI fuerce la creación manual de sesiones primero (alcance de Fase 2 / drag-drop), se cambia el handler. Por ahora: la UI muestra "Añadir bloque" sin requerir sesión previa; el docente no ve fricción.

2. **Defaults seguros en `createBloque`:** `tipo='desarrollo'`, `nivel_flexibilidad='abierto'`, `origen='maestra'`. P-PD9 preservado (la IA nunca crea estado; sólo sugiere). El docente puede ajustar tipo/nivel en una iteración futura si el alcance lo permite.

3. **Edición inline en `BloqueEditor`** usa `origen='maestra_editado_de_ia'` aunque sea una edición sin IA. Razón: el enum `bloque.origen` no tiene un valor para "edición manual post-creación", y el helper `updateBloque` en `update-actions.ts:22-23` valida zod contra `['ia_sugerencia', 'maestra_editado_de_ia']` (no permite `'maestra'`). Si INTEGRA prefiere relajar el schema/zod para aceptar edición manual con `origen='maestra'`, es cambio aditivo. Decisión documentada para no bloquear.

4. **F3 sugiere los 4 campos a la vez** (`problema_contexto`/`proposito`/`producto_integrador`/`ajustes_razonables`) con un único POST. La SPEC_TEC_08 §4.2 `camposPulir?: string[]` permite subset, pero la UI mínima siempre pide los 4 para máxima utilidad (Tía Lola). Si la docente quiere subset, queda como evolución (selector).

5. **`IASugerenciaPanel` para F3** no se instancia por bloque (vive en la cabecera de la planeación). Coherente con el contrato `bloque.origen` (F1/F2 sí afectan bloque; F3 afecta planeación). Por bloque: F1+F2 sólo.
