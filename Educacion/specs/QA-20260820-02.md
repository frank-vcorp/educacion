## D. Hallazgos priorizados

### P3-1 — `migrations_master.sql`: orden de append (§0022 antes de §0015) rompe `set_updated_at()` si se aplica el master desde cero
- **Evidencia:** `supabase/migrations_master.sql:801` (§0022) precede a `:840` (§0015). El trigger `trg_entrevista_updated` (línea 829) referencia `set_updated_at()` que se define en línea 845. Si se aplica `migrations_master.sql` desde cero (p.ej. en un seed reset), la creación del trigger fallará con "function set_updated_at() does not exist".
- **Impacto:** Bajo. El flujo operativo real usa `supabase db push` que aplica cada archivo por nombre numérico (0015 < 0022 → función disponible). El master file es artefacto de concatenación. SOFIA siguió el patrón existente (0021 ya está antes de 0015 en líneas 786-794, también rompe si se aplica master desde cero). No es regresión introducida por este IMPL; es patrón pre-existente.
- **Recomendación:** Reordenar `migrations_master.sql` para que §0015 preceda a §0020/§0021/§0022 (mejora de mantenibilidad). No bloquea `supabase db push`. SOFIA vía INTEGRA (L3, no contractual).
- **Condición de cierre:** Si se reordena, todos los 0020/0021/0022 pasan a la sección posterior a 0015.

### P3-2 — Pre-poblado de ítem 19 (Grado) cae en cadena vacía por `alumno.grado` no provisto por el caller
- **Evidencia:** `app/(app)/alumnos/alumnos-manager.tsx:263` usa `(entrevistaTarget as unknown as { grado?: string }).grado ?? ''`. El tipo `Alumno` (línea 26) solo tiene `id`, `nombre`, `created_at`. La query en `app/(app)/alumnos/page.tsx:51-56` selecciona `id, nombre, created_at` de la tabla `alumno`. Por tanto, `alumno.grado` siempre es `''` en runtime, y `buildRespuestasVacias` (en `entrevista-inicial-form.tsx:93-98`) deja el ítem 19 con respuesta vacía por defecto. La docente puede editarlo manualmente. El SPEC §4 acepta derivar de `alumno.grado`/`grupo.grado` (línea 105); la alternativa `grupo.grado` sí está disponible vía `grupo: GrupoLite` (línea 39), pero no se está usando.
- **Impacto:** Bajo. No es defecto del contrato (el ítem 19 es editable y pre-poblable desde cualquiera de las dos fuentes). Pero la implementación actual no pre-puebla el ítem 19, perdiendo UX. La docente lo llena a mano.
- **Recomendación:** Cambiar `buildRespuestasVacias({ ..., grado: grupo.grado, ... })` (que sí está disponible en `GrupoLite`) o bien extender la query del page para incluir `grado` del alumno. SOFIA vía INTEGRA (L2, mejora UX; ≤10 líneas).
- **Condición de cierre:** Ítem 19 pre-poblado con el grado del grupo/alumno en la primera carga.

### P3-3 — Test unit de server actions: cobertura de "no-IA estática" no incluye `app/api/recursos-aula/ia-sugerir-uso`
- **Evidencia:** `tests/unit/services/alumnos/entrevista-actions.spec.ts:11` declara "Lista negra: no se importa desde app/api/ia, services/ia ni lib/ia (AC-8)" pero no ejecuta el grep; solo doc-text. El test no enforza el contrato automáticamente.
- **Impacto:** Bajo. Una regresión futura que importe `entrevista-actions` desde la capa IA no sería atrapada por el test suite. El test documenta la regla, no la garantiza.
- **Recomendación:** Añadir un test que ejecute `grep` o `readdir` sobre las rutas IA y falle si encuentra la cadena `entrevista_inicial_alumno` o `entrevista-actions`. O bien un test de tipo `expect(() => import('@/app/api/planeaciones/[id]/ia/pulir-pdf/route')).not.toThrow()` con assert de no-imports transitivos. SOFIA vía INTEGRA (L2, mejora cobertura; ≤30 líneas).
- **Condición de cierre:** Test añadido al CI que falla si cualquier archivo en `app/api/**/ia/*`, `services/ia/*`, `lib/ia/*` importa `@/services/alumnos/entrevista-actions` o referencia `entrevista_inicial_alumno`.
